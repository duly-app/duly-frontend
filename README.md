# Duly Frontend

Single-page web client for Duly, a note-taking app. Users log in, browse and manage their notes,
and (once the service lands) talk to an assistant about them.

## Overview

The app is a Vite-built React SPA. It holds no data of its own — it authenticates against
`duly-backend` and reads and writes notes through that service's JSON API under `/api`. The
assistant panel will talk to `duly-chat-backend`, which is still in development.

Authentication is JWT-based. The token and current user live in an auth context
(`src/features/auth/context`), and route-level pages consume it through the `useAuth` hook.

## Stack

- **React 19** with TypeScript, built by **Vite**
- **Tailwind CSS 4** for styling
- **shadcn/ui** — the base-ui variant (`base-nova` style), with **lucide** icons
- **React Router 7** for routing
- **oxlint** for linting, **prettier** for formatting

## Prerequisites

- Node — version in `.nvmrc` (`nvm use` picks it up)
- Docker, for the development database
- A local `duly-backend` checkout, since the frontend has no data without it

## Local Development

The frontend needs the backend and its database to be useful, so development means three
processes. Nginx is deliberately left out — Vite's dev proxy replaces it.

**1. Database** — from the `note-taking-app` directory:

```bash
docker compose -f docker-compose.dev.yml up duly-postgres
```

Only this service. Bringing up the others would shadow the processes you're debugging.

**2. Backend** — run the `Flask` configuration in `duly-backend/.vscode/launch.json`. It serves on
port 5001 and connects to the containerized Postgres on `localhost:5432`.

**3. Frontend:**

```bash
npm install
npm run dev
```

Then open http://localhost:5173.

Vite proxies `/api` to `http://localhost:5001` (see `vite.config.ts`), which is why the backend's
local port differs from the 5000 it uses inside Docker — the two setups can run side by side
without colliding.

## Scripts

| Script                 | Purpose                                        |
| ---------------------- | ---------------------------------------------- |
| `npm run dev`          | Vite dev server with HMR                       |
| `npm run build`        | Typecheck (`tsc -b`) then build for production |
| `npm run preview`      | Serve the production build locally             |
| `npm run lint`         | oxlint                                         |
| `npm run format`       | Rewrite files with prettier                    |
| `npm run check-format` | Fail if anything is unformatted (what CI runs) |

## Structure

- `src/pages` — route-level pages, one directory per route (`home`, `login`)
- `src/features` — feature slices; each owns its `api`, `components`, `context` and `types`
- `src/components/ui` — primitives generated by the shadcn CLI. Prettier ignores this directory so
  reformatting doesn't fight regeneration; change these by re-running the CLI where possible.
- `src/lib` — shared helpers, including the `cn` class-merging utility
- `vite.config.ts` — build config, the `@` path alias, and the dev proxy

## CI/CD

GitHub Actions runs on every pull request (and in the merge queue):

- **`pr-checks.yml`** — two jobs. _Check Formatting_ runs oxlint and `prettier --check`; _Build_
  runs `npm run build`, which typechecks via `tsc -b` before bundling, so there's no separate
  typecheck job.
- **`commitlint.yml`** — enforces conventional commit messages.

Both jobs take the Node version from `.nvmrc` and cache npm downloads between runs. Concurrent runs
for the same pull request are cancelled so only the newest commit is checked.

There is no deployment pipeline yet. `Dockerfile.dev` exists for the Docker Compose development
setup only; the production image build and the Kubernetes manifests under `k8s/frontend` are not
wired into CI.
